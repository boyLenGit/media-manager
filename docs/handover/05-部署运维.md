## 2. 为什么部署这么麻烦?(核心背景)

DSM 7.1 的 **Docker 套件是 20.10.3**(2021 年的老版本),导致:

1. **拉 ghcr.io 镜像失败**:老 docker 不识别新 OCI image index / manifest 格式
   - 已修:CI 用 `outputs: type=registry,manifest:type=docker` + `provenance: false` 推**旧 v2 manifest**
2. **`docker pull` 从 ghcr.io / docker.io 又慢又卡**:GitHub / Docker Hub CDN 对国内 NAS 不友好,经常超时
3. **不能随便重启 dockerd**:会影响同机的 Clash/yacd/baiduapp 等容器

**最终定型:方案 C** — 不让 NAS 直接 pull,改成"外部机器拉镜像 → scp 传 tar → docker load"。

---

## 3. 部署 / 更新流程(方案 C)⭐

在**能上网的机器**(用户 Mac,在 NAS 局域网内)执行:

```bash
# 1. Mac 拉镜像打包成 tar(纯 Python,不需要 docker)
cd /tmp && python3 <项目>/docs/scripts/pull-image.py \
    ghcr.io/boylengit/media-manager:latest /tmp/mm-latest.tar amd64

# 2. scp 到 NAS(必须加 -O!DSM OpenSSH 8.2 不支持新 sftp 协议)
sshpass -p '<密码>' scp -O -P 4999 /tmp/mm-latest.tar bo@192.168.2.176:/tmp/

# 3. NAS 上加载 + 重启
sshpass -p '<密码>' ssh -p 4999 bo@192.168.2.176 "
  echo '<密码>' | sudo -S /var/packages/Docker/target/usr/bin/docker load -i /tmp/mm-latest.tar &&
  cd /volume1/docker/media-manager &&
  echo '<密码>' | sudo -S /usr/local/bin/docker-compose up -d &&
  rm /tmp/mm-latest.tar"

# 4. 验证(应返回最新 commit)
curl -s http://192.168.2.176:10001/api/health
```

### pull-image.py 支持

- **registry**:ghcr.io、docker.io、以及国内镜像(`registry.cyou`、`docker.xuanyuan.me` 匿名可用)
- **断点续传**:layer 按 size 校验,已下完的跳过(大镜像中断可续)
- 用法:`pull-image.py <image:tag> <out.tar> [arch]`

### migration 自动跑

新镜像启动时 lifespan 自动执行未跑的 migration(如 0005~0008),**无需手动**。部署后验证:
```python
# 容器内 python3
from sqlalchemy import text; from app.db.session import engine
with engine.begin() as c:
    print(c.execute(text('SELECT * FROM schema_version')).fetchall())
```

## 4. `update.sh` 能不能用?

`docs/scripts/update-on-synology.sh` 里跑的是 `docker-compose pull`,**在当前 NAS 上会卡死**(就是上面说的 ghcr.io pull 问题)。所以:

- **DSM 7.1(现状)**:❌ 不能用 update.sh,必须走方案 C
- **升级 DSM 7.2 后**:✅ Docker 升到 24.x,`docker pull ghcr.io` 直接通,update.sh 可用(路径要改成 `docker compose` / ContainerManager 路径)

## 5. 端口转发 / 权限相关的坑

### /volume1/sys 权限(ACL)

`/volume1/sys` 有群晖 ACL,容器裸 `1026:100` 读不了。解决:建 `docker_boy_auto` 组(GID 65536),给该组 `/volume1/sys` 读权限,compose 加 `group_add: ["65536"]`。原理见 08 或早期对话。

### scp 必须加 -O

DSM 的 OpenSSH 8.2 不支持新版 sftp 子系统协议,`scp` 不加 `-O`(强制用旧 SCP 协议)会失败。

### sudo 密码

NAS 上执行 sudo 命令模板:`echo '<密码>' | sudo -S <cmd>`。

## 6. CI(GitHub Actions)

- 文件:`.github/workflows/docker-publish.yml`
- 触发:push 到 master
- 产物:`ghcr.io/boylengit/media-manager:latest`(+ commit tag)
- **关键参数**(为兼容老 docker):
  ```yaml
  outputs: type=registry,manifest:type=docker   # 推旧 v2 manifest
  provenance: false                              # 不加 provenance(否则变 OCI index)
  ```
- 前端构建强制 `FROM --platform=$BUILDPLATFORM`(避免 QEMU 跑 amd64 build OOM)
- 用 pnpm 替代 npm(npm 在 CI 有 "Exit handler never called" 问题)
- 构建约 6-8 分钟

| 项 | 7.1 现状 | 7.2 后 |
|---|---|---|
| Docker | 20.10.3 | 24.0.x |

升级注意:容器会重启 1-2 次;`update.sh` 里 docker-compose 路径要从 `/usr/local/bin/docker-compose` 改成 `docker compose`(ContainerManager 版)。数据在 bind mount,不受影响。

## 8. 快速命令速查

```bash
# NAS 上 docker/compose 绝对路径(套件版)
DOCKER=/var/packages/Docker/target/usr/bin/docker
DC=/usr/local/bin/docker-compose

# 看容器状态
sudo $DOCKER ps

# 看 media-manager 日志
sudo $DOCKER logs --tail 100 media-manager

# 重启
cd /volume1/docker/media-manager && sudo $DC up -d

# 进容器
sudo $DOCKER exec -it media-manager bash

# 健康检查(带 commit)
curl -s http://192.168.2.176:10001/api/health
```
