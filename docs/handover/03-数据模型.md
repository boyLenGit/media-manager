# 03 · 数据模型

## 1. 数据库概况

- **SQLite**,文件在容器内 `/app/backend/data/media_manager.db`(NAS 上映射到 `/volume1/docker/media-manager/data/`)
- **WAL 模式 + 外键约束**(见 `db/session.py`)
- **共 22 张表**(含 FTS5 虚拟表)
- 所有表定义在 `backend/app/models/__init__.py`,是 SQLModel 类

---

## 2. 表清单(按领域分组)

### 核心资源域

| 表 | 作用 | 关键字段 |
|---|---|---|
| **media_item** | 一个"资源条目"(一部影片/一个视频作品) | title, normalized_title(去噪后标题,用于去重), media_type_id, author_id, cover_path, rating, favorite, watch_status(unwatched/watching/watched) |
| **file_asset** | 磁盘上的一个物理文件 | path(唯一), partial_hash(头尾各 1MB 哈希), file_type(video/subtitle/image/metadata), missing, media_probe_json(ffprobe 原始结果) |
| **media_file** | media_item ↔ file_asset 的关联(一对多) | quality, container, video_codec, audio_codec, width, height, duration_seconds, is_primary(主文件标记) |
| **media_tag** | media_item ↔ tag 多对多 | (media_item_id, tag_id) 复合主键 |

**为什么 media_item 和 file_asset 分开?** 一个作品可能有多个文件(1080p / 4K / 不同字幕版),所以 media_item 是逻辑作品,file_asset 是物理文件,中间 media_file 关联。同名不同清晰度会合并到一个 media_item。

### 字典 / 分类域

| 表 | 作用 |
|---|---|
| **media_type** | 资源类型(电影/剧集/动漫/教程...,用户可自定义) |
| **author** | 作者/UP主/制作方 |
| **tag** | 标签(带 group_name 分组 + color;"知识点"这类书签标签也复用此表) |

### 扫描域

| 表 | 作用 | 关键字段 |
|---|---|---|
| **scan_path** | 用户配置的扫描目录 | path(容器内路径), recursive, enabled, last_scan_at |
| **scan_job** | 一次扫描任务 | status(pending/running/enriching/dedup/success/failed), phase, total_files/scanned_files, enrich_total/enrich_done, dedup_total/dedup_done/dedup_groups_found |
| **scan_log** | 扫描过程日志 | level, message, file_path |

`scan_job` 的多阶段字段是三阶段扫描进度的核心(见 04 功能清单)。

### 书签域(0008 新增)

| 表 | 作用 | 关键字段 |
|---|---|---|
| **bookmark** | 视频时间点书签 | media_item_id, file_asset_id?, position_seconds, title, note, created_by |
| **bookmark_tag** | bookmark ↔ tag 多对多 | 复用 tag 表 |

### 下载 / 搜索域

| 表 | 作用 |
|---|---|
| **resource_source** | 搜索源配置(Torznab URL + API key) |
| **search_result** | 搜索结果缓存(含 matched_media_id 去重标记) |
| **download_task** | qBittorrent 下载任务(info_hash, magnet_uri, status, progress) |

### 播放域

| 表 | 作用 |
|---|---|
| **playback_target** | 播放目标配置(jellyfin / external_url / smb_path / custom_protocol) |
| **playback_history** | 播放历史 + 续播位置(position_seconds) |

### 去重

| 表 | 作用 |
|---|---|
| **duplicate_match** | 重复检测结果(match_level: exact/high/medium) |

### 认证 / 系统

| 表 | 作用 |
|---|---|
| **user** | 用户(role: admin/user, argon2 password_hash, enabled) |
| **revoked_token** | 已撤销的 JWT jti 黑名单(登出/强制下线) |
| **app_setting** | KV 配置表(下载器配置、解析器顺序、SMB 配置等都存这) |
| **audit_log** | 审计日志(0006 新增,append-only,记敏感操作) |

### 全文搜索

| 表 | 作用 |
|---|---|
| **media_search_fts** + 附属表 | SQLite FTS5 虚拟表,标题/作者/标签全文索引 |

## 3. 核心关系图

```
media_type ──┐
author ──────┤
             ↓
        media_item ──< media_file >── file_asset
             │                            │
             ├──< media_tag >── tag       └── scan_path(来源)
             │                    ↑
             └──< bookmark ──< bookmark_tag >┘
                     │
                     └── user(created_by)

resource_source ──< search_result
download_task
playback_target / playback_history
scan_path ──< scan_job ──< scan_log
user ──< revoked_token / audit_log
app_setting(KV,独立)
```

`──<` 表示一对多,`>──` 表示多对一,`< X >` 表示多对多中间表。

## 4. Migration 机制(重要 · 无 Alembic)

### 设计

- **手写 SQL 文件**放 `backend/app/db/migrations/`,命名 `000N_描述.sql`
- **轻量执行器** `db/migrate.py` 在启动时(main.py lifespan)自动跑
- 用 `schema_version` 表记录已执行的迁移(字段:version, applied_at)
- **幂等**:已执行的跳过,只跑新的

### 现有迁移

| 文件 | 内容 |
|---|---|
| `0001_init.sql` | 18 张业务表 + FTS5 |
| `0002_seed.sql` | 默认类型/标签/播放目标 |
| `0003_auth.sql` | user / revoked_token |
| `0004_rebrand.sql` | MediaHub→Media Manager 品牌迁移(改 custom_protocol scheme 等) |
| `0005_scan_job_phases.sql` | scan_job 加 enrich_total/done + phase(两阶段进度) |
| `0006_audit_log.sql` | audit_log 表 |
| `0007_scan_dedup_phase.sql` | scan_job 加 dedup_total/done/groups_found(第三阶段) |
| `0008_bookmark.sql` | bookmark + bookmark_tag 表 |

### 加新迁移的规矩 ⚠️

1. **新建** `000N_xxx.sql`,**绝不改老文件**(老文件已在生产库执行过)
2. SQLite 的 `ALTER TABLE ADD COLUMN` 是安全的(加列带 default)
3. **同步更新** `models/__init__.py` 里对应的 SQLModel 类字段
4. 本地测试:删 `backend/data/*.db*` 重启,让迁移从头跑一遍验证
5. 部署后验证:
   ```python
   # 容器内
   from sqlalchemy import text
   from app.db.session import engine
   with engine.begin() as c:
       print(c.execute(text('SELECT * FROM schema_version')).fetchall())
   ```

### 踩过的坑

- **SQLAlchemy 保留字 `metadata`**:AuditLog 表有个 metadata 列,SQLModel 类里必须用别名 `metadata_json: ... = Field(sa_column=Column("metadata", Text))`,否则和 declarative base 的 `metadata` 冲突。
- **FTS5 表不能用 SQLModel 映射**:media_search_fts 是虚拟表,只能用原生 SQL 操作(见 search_service.py)。
