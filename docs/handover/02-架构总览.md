# 02 · 架构总览

## 1. 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | **Python 3.11 + FastAPI** | 异步 Web 框架 |
| ORM | **SQLModel**(SQLAlchemy + Pydantic) | 表定义即 Python 类 |
| 数据库 | **SQLite**(WAL 模式) | 单文件,NAS 友好,不需要独立 DB 服务 |
| 迁移 | **手写 SQL + 轻量执行器** | 无 Alembic(见 03) |
| 认证 | **JWT(access+refresh) + argon2** | `pyjwt` + `argon2-cffi` |
| 任务 | **asyncio.Queue + apscheduler** | 扫描单消费者队列 + 下载轮询 |
| 媒体 | **ffprobe / ffmpeg** | 探测编码 + 生成缩略图 |
| 前端 | **Vue 3 + TypeScript + Vite** | Composition API |
| UI 库 | **Element Plus** | |
| 状态 | **Pinia** | 只用于 auth |
| 播放器 | **Artplayer + hls.js** | 网页播放 |
| 部署 | **Docker 单容器 + GitHub Actions CI** | 多阶段构建,前后端打一个镜像 |

## 3. 启动流程(main.py lifespan)

```
1. get_settings()          读 env 配置
2. setup_logging()         配置日志
3. run_migrations()        跑 db/migrations/*.sql(幂等,已执行的跳过)
4. ffprobe_service.check() 检查 ffmpeg 是否可用(不阻塞,只打日志)
5. scan_worker.start()     启动扫描队列消费者
6. download_sync.start()   启动 qB 状态轮询
--- 服务运行 ---
7. 关闭时 stop 两个 worker
```

前端静态资源:生产模式下 Dockerfile 把 Vue build 产物放进镜像,后端用 `StaticFiles` 挂 `/assets`,其余路径 fallback 到 `index.html`(支持 Vue Router history 模式)。

## 4. 请求数据流(以"扫描"为例)

```
用户点扫描
  → 前端 POST /api/scan/paths/{id}/scan
    → api/scan.py 校验 → scan_worker.enqueue(path_id)
      → asyncio.Queue(单消费者,避免 SQLite 写锁竞争)
        → scan_service.run_scan_job():
           Phase 1: 建 ScanJob 记录
           Phase 2: os.walk 列文件(过滤扩展名)
           Phase 3: 逐文件 upsert FileAsset + 建 MediaItem/MediaFile
           Phase 4: 标记失踪文件
           Phase 5: [status=enriching] ffprobe 探测 + ffmpeg 缩略图(并发2,实时刷进度)
           Phase 6: 中段收尾
           Phase 7: FTS5 索引同步
           Phase 8: [status=dedup] 全库重复检测(仅末尾 job 跑,分桶优化)
           Phase 9: [status=success] 完成
  ← 前端每 2s 轮询 /api/scan/jobs 显示进度条(扫描→后处理→查重)
```

## 5. 四大扩展点(provider 模式)⭐

这是项目**最舒服的扩展点**,加新东西不动核心:

| provider 目录 | 已实现 | 抽象基类 | 加新的做法 |
|---|---|---|---|
| `providers/parser/` | Bilibili / Anime / Default | `ParserPipeline` | 写一个 parser 类,注册进 pipeline,设置页可调顺序 |
| `providers/search/` | Torznab(Jackett/Prowlarr) | `SearchProvider` | 实现 search 接口(如 RSS 源) |
| `providers/downloader/` | qBittorrent | `DownloaderProvider` | 实现 add_magnet/get/list 等(如 Transmission/aria2) |
| `providers/player/` | Jellyfin | — | 加播放目标类型 |
| `providers/metadata/` | (空,预留) | — | 海报刮削(TMDB/豆瓣)未来放这 |

**解析器 pipeline** 是最典型的:配置存在 `app_setting` 表(key=`active_parsers`),用户在"设置→解析器"里拖拽顺序,扫描时按顺序尝试解析文件名。

## 6. 关键约定

- **api 薄,service 厚**:路由函数只做校验 + 调 service。
- **SQLite 写操作单线程化**:扫描走单消费者队列,避免并发写锁。
- **敏感操作**:删除/清空→二次确认;危险区→密码验证;都写 `audit_log`。
- **真实文件默认不动**:删资源默认只清 DB,除非显式 `delete_files=true`。
- **中文注释 + conventional commit**(`feat(scope): xxx`)。
