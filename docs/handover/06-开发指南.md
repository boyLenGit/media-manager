## 3. 改数据库 schema

**步骤(必须按顺序)**:

1. 新建 `backend/app/db/migrations/000N_描述.sql`(N 递增,**不改老文件**)
2. 写 SQL(SQLite 方言;`ALTER TABLE ADD COLUMN ... DEFAULT ...` 安全)
3. 同步改 `backend/app/models/__init__.py` 对应 SQLModel 类字段
4. 本地删库重启,让迁移从头跑一遍验证不报错
5. 前端 `api/*.ts` 补对应字段类型

**注意**:
- 保留字冲突(如 `metadata`)用 `Field(sa_column=Column("列名", 类型))` 别名
- FTS5 虚拟表不能 SQLModel 映射,用原生 SQL

## 4. 加一个新 provider(最舒服的扩展点)

### 新文件名解析器

```python
# backend/app/providers/parser/my_parser.py
from app.providers.parser.base import BaseParser, ParseResult

class MyParser(BaseParser):
    name = "my_parser"
    def parse(self, filename: str) -> ParseResult | None:
        # 匹配得上返回 ParseResult,否则 None(交给下一个 parser)
        ...
```
注册进 `pipeline.py` 的可用列表,用户在"设置→解析器"里启用/排序。

### 新下载器(如 Transmission)

```python
# backend/app/providers/downloader/transmission.py
from app.providers.downloader.base import DownloaderProvider, TorrentInfo

class TransmissionProvider(DownloaderProvider):
    name = "transmission"
    async def add_magnet(self, magnet, save_path=None, category=None) -> str: ...
    async def get(self, task_id) -> TorrentInfo | None: ...
    async def list_all(self) -> list[TorrentInfo]: ...
    async def pause/resume/remove/get_files(...): ...
```
在 `downloader/factory.py` 的 `create_provider` 里加分支。

### 新搜索源 / 播放目标

同理,分别实现 `providers/search/` 和 `providers/player/` 的接口。

## 5. 加一个新 API

1. 在 `api/` 建或改路由文件(用 `APIRouter()`)
2. 薄:只做校验 + 调 `services/` 里的函数
3. 在 `api/__init__.py` 注册:
   ```python
   api_router.include_router(xxx.router, prefix="/xxx", tags=["xxx"], dependencies=protected)
   ```
   - `dependencies=protected` = 需登录;不加 = 公开
   - 需要 admin:函数参数加 `_admin: User = Depends(require_admin)`
4. 前端建 `frontend/src/api/xxx.ts` 封装
5. 敏感操作:写 `audit_service.record(...)`

- 改动 1

scope:`backend` / `frontend` / `ci` / `deploy` / `docs` / `scripts` / 具体模块名。

### 部署自测流程

改完前端:`npm run type-check` → `npm run build`。
改完后端:`ast.parse` 语法检查(没有完整本地环境时至少这个)。
两个都过再 commit → push → CI 构建 → 方案 C 部署。

## 8. 明确不要做的事 🚫

- **不引入 Alembic** — 已有轻量迁移器,够用
- **不换 ORM** — SQLModel 已定
- **不装 Redis / PostgreSQL** — NAS 场景 SQLite 够,加这些是过度工程
- **不给前端加 Vuex** — 只用 Pinia
- **不改老 migration 文件** — 只新建
- **不动 NAS dockerd 配置**(除非明确要) — 会影响其他容器
- **不把密码 / 真实 IP / 路径写进文档或代码** — 用占位符
- **不追求测试覆盖率** — 纯逻辑模块可以加 pytest,但别为覆盖率而写

## 9. 给下一个 agent 的上手建议

1. **先跑通本地**(装依赖、起前后端、登录看到资源库)
2. **读 `main.py` + `api/__init__.py`** 理解入口和路由组织
3. **挑一个具体扩展点做小功能** — 推荐先写一个新解析器或搜索源 provider,最舒服
4. **改 schema 走 migration**,别改老文件
5. **遇到坑先翻 08-运维知识库 和 07-已知问题**,大概率前人踩过
