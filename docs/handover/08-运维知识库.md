## 1. qBittorrent 下不动,BitComet 却能下?

**这是环境问题,不是 bug。**

### 原理

标准 BT 客户端(qB)找 peer 只有 4 个渠道:Tracker(HTTP/UDP)、DHT(UDP)、PEX、LSD。国内电信/移动宽带常**屏蔽 BT tracker 端口**(6969、1337 等)和部分 UDP,导致 qB 找不到 peer。

**BitComet 有"歪门左道"**:
- **自家长效种子库**:所有 BitComet 用户下过的资源都注册到 BitComet 服务器,你下时它从这个中心化索引补 peer
- **HTTP/FTP 镜像**:.torrent 的 `url-list` 字段(BEP-19)指向 HTTP 镜像,直接从 CDN 下,不走 BT
- **ed2k 混合**:同时跑电驴协议

这些都走**普通 HTTPS 域名**,运营商不拦 → BitComet 能下。

### 验证方法

```bash
# 在 NAS 上测出站到 BT tracker(TCP timeout = 被拦)
python3 -c "
import socket
for h,p in [('tracker.opentrackr.org',1337),('tracker.openbittorrent.com',6969)]:
    try:
        s=socket.socket(); s.settimeout(3); s.connect((socket.gethostbyname(h),p)); s.close()
        print(h,'OK')
    except Exception as e: print(h,type(e).__name__)
"
# 用 Ubuntu 官方公开种子测(seeder 海量)— 若也下不动 = 网络层问题,非种子冷
```

### 解决(如果非要 qB 快)

1. **qB 走代理**:设置→连接→代理,指向支持 UDP 的 Clash 节点(`192.168.2.176:7890`)。注意 PT 站走代理可能封号
2. **路由器端口转发**:把 qB 监听端口(如 61459)在路由器/光猫转发到 NAS,让外网 peer 能连进来
3. **PT 站资源必须用 qB**:PT 私有 tracker 不被拦,且 BitComet 会被 PT 封号

### 已做的 qB 优化(通过 API 应用)

- 全局连接 500→1000,单 torrent 100→200
- 开启自动加 13 个公共 tracker
- DHT/PEX/LSD 全开
- 这些对**能下的资源**都是正收益,但治不了"tracker 被拦"的根

## 2. NAS 拉镜像卡死怎么办?

老 DSM Docker + 国内网络,`docker pull` ghcr.io/docker.io 经常卡。

**方案 C**:外部机器(Mac)拉 → scp → docker load。见 05-部署运维。

`pull-image.py` 支持的可用镜像源(截至 2026-06):
- `ghcr.io`(项目镜像,匿名可拉)
- `registry.cyou` / `docker.xuanyuan.me`(docker hub 镜像,**匿名可用**,拉 linuxserver 等第三方镜像)
- `docker.io`(直连,通常国内卡)
- `docker.1ms.run` / `docker.m.daocloud.io`(需账号,匿名多半被拒)

拉第三方镜像示例:
```bash
python3 pull-image.py registry.cyou/linuxserver/prowlarr:latest /tmp/prowlarr.tar amd64
# load 后镜像名带 registry.cyou 前缀,需 docker tag 成 compose 里写的名:
sudo docker tag registry.cyou/linuxserver/prowlarr:latest linuxserver/prowlarr:latest
```

## 3. 接入 Prowlarr / Jackett 搜索源

Prowlarr 已部署在 NAS(9696)。完整步骤见 `docs/tutorials/jackett-prowlarr_cn.md`。要点:

1. 浏览器开 `http://192.168.2.176:9696` 设管理密码
2. Settings → General → API Key 复制
3. Indexers → Add Indexer 加 BT 站(公开:1337x/yts/nyaa;私有 PT 要 cookie)
4. Media Manager → 设置→搜索源 → 加 Torznab 源:
   - URL: `http://192.168.2.176:9696/<indexer_id>/api`
   - API Key: 上面复制的
5. **每个 indexer 建一条搜索源**(当前 Torznab adapter 不支持 all 聚合路径)

Prowlarr 部署记录:用 `registry.cyou` 镜像拉的 `linuxserver/prowlarr`,配置在 `/volume1/docker/prowlarr/`。

## 4. /volume1/sys 容器读不了(Permission denied)

**原因**:群晖共享文件夹有 SynoACL,容器裸 `1026:100` 身份不带 ACL 上下文,读不了。

**解决**(已做):
1. DSM 控制面板建组 `docker_boy_auto`(GID 65536)
2. File Station 给该组 `/volume1/sys` 读权限
3. compose 加 `group_add: ["65536"]`

验证:`sudo docker exec media-manager ls /media/sys` 能列出内容。

## 5. 部署后前端还是旧版?

浏览器缓存。**`Cmd/Ctrl + Shift + R` 强刷**。确认版本:`curl http://192.168.2.176:10001/api/health` 看 commit。

## 6. scp 传文件失败?

DSM OpenSSH 8.2 不支持新 sftp 协议。scp **必须加 `-O`**(大写,强制旧 SCP 协议)。

## 7. 常用排障命令

```bash
# 容器日志
sudo /var/packages/Docker/target/usr/bin/docker logs --tail 100 media-manager

# 看 qB 任务状态(API)
curl -s -c /tmp/c -d "username=admin&password=xxx" -H "Referer: http://192.168.2.176:8095" \
  http://192.168.2.176:8095/api/v2/auth/login
curl -s -b /tmp/c http://192.168.2.176:8095/api/v2/torrents/info | python3 -m json.tool

# 看 media-manager 下载任务
TOKEN=$(curl -s -X POST http://192.168.2.176:10001/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"boylen","password":"xxx"}' \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['access_token'])")
curl -s -H "Authorization: Bearer $TOKEN" http://192.168.2.176:10001/api/downloads

# 查 migration 状态
sudo docker exec media-manager python3 -c "
from sqlalchemy import text; from app.db.session import engine
with engine.begin() as c: print(c.execute(text('SELECT * FROM schema_version')).fetchall())"

# 看 NAS 上所有容器
sudo docker ps --format '{{.Names}}\t{{.Status}}\t{{.Ports}}'
```

## 8. 危险区"抹掉所有内容"用法

用户输错用户名想重来 → 设置→危险区→输管理员密码→清空(除当前 admin 外一切,不动磁盘视频)。清完强制重登。审计日志会记一条(但 audit_log 本身不被清)。

## 9. 生产环境敏感信息

- NAS SSH / sudo 密码、JWT_SECRET 等**不写进文档和代码**,只在运行时通过环境变量传
- 用户的 qB / Prowlarr 密码等由用户自己管理
- 文档里一律用占位符 `<密码>` / `<nas-ip>`
